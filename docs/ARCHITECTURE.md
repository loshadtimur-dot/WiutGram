# Архитектура UNI Lovers

Монолит на Node.js: один процесс Express обслуживает API, раздаёт статику и
держит Socket.IO. Данные — SQLite (WAL) на том же сервере, файлы — на диске.

```
Браузер (SPA, vanilla JS + ES-модули)
   │  HTTPS (Caddy) ── статика /css /js /img, HTML, /uploads (реклама), /media (фото)
   │  WSS /socket.io
   ▼
Node.js (server.js)
   ├── routes/*            REST API (/api/...)
   ├── routes/admin/*      только роль owner (иначе 404)
   ├── lib/*               доменная логика: свайпы, матчи, лимиты, реклама, 2FA
   ├── middleware/*        auth, CSRF, rate limit, upload, валидация
   ├── db/*                схема, миграции (аддитивные), сиды
   └── data/app.db         SQLite (WAL), uploads/, storage/
```

## Поток запроса

1. Caddy принимает HTTPS, ставит `X-Forwarded-Proto`/`X-Forwarded-For`,
   проксирует на `127.0.0.1:3000`.
2. `server.js` подключает `helmet`, сжатие, cookie-parser, сессионную
   аутентификацию (JWT в HttpOnly-куке), CSRF-проверку Origin на мутациях.
3. Роутер проверяет права (`requireAuth`, `requireOwner`, `requireSudo`),
   валидирует входные данные и работает с БД через `db.js`.
4. Ответ отдаётся как JSON; SPA рисует страницу.

## Аутентификация и роли

- JWT в HttpOnly-куке `uni_token`; за HTTPS — `Secure; SameSite=None; Partitioned`,
  по HTTP — `SameSite=Lax`.
- Сессии в таблице `sessions`; `users.token_version` позволяет разом отозвать все
  токены (смена пароля, сброс владельца).
- Роли: `owner` (первый реальный аккаунт) и `user`. Владельца нельзя удалить,
  забанить или понизить; опасные действия требуют sudo-подтверждения паролем.
- 2FA владельца: TOTP, секрет шифруется AES-256-GCM ключом из `JWT_SECRET`
  (или `data/secret.txt`), резервные коды — SHA-256, блокировка после 5 неудач.

## Ключевые таблицы

| Таблица | Назначение |
| --- | --- |
| `users`, `profiles` | аккаунт, профиль, настройки приватности |
| `photos` | фото профиля (пути к файлам) |
| `swipes` | лайки/пропуски/суперлайки, по одной записи на пару |
| `matches`, `messages` | взаимные лайки и переписка |
| `posts`, `post_likes`, `post_comments`, `post_views` | лента |
| `stories`, `story_views` | истории на 24 часа |
| `notifications` | уведомления |
| `blocks`, `reports` | блокировки и жалобы |
| `universities` | справочник вузов (редактируется владельцем) |
| `ad_*` | реклама: баннеры, кампании, слоты по часам, заявки, статистика |
| `superlike_orders`, `users.super_likes_bonus` | покупка суперлайков |
| `site_settings` | настройки сайта и рекламы (ключ-значение) |
| `activity_log` | журнал действий владельца |
| `sessions` | активные сессии |

## Реклама

- Слот уникален: `UNIQUE(placement, hour_start)`; час продаётся один раз, гонка
  закрывается транзакцией.
- Время — unix-секунды UTC, отображение и сетка — по Ташкенту (UTC+5).
- Показ в час: активная кампания → баннер; иначе «свой блок» или пусто.
- Показы считаются уникальными на посетителя в час (`ad_views`).
- Реквизиты для оплаты — только по флагу `ads_show_card`; иначе публичный API их
  не отдаёт.

## Файлы

- `uploads/` — публичные файлы (баннеры рекламы, демо-аватары).
- `storage/` — зарезервировано под приватные медиа (план: перекодирование,
  случайные имена, выдача через авторизованный `/media/:id`).
- `data/` — БД, WAL, бэкапы, `secret.txt`.

## Развёртывание

`deploy/`: Caddy (HTTPS, HSTS, лимит тела, noindex для `/admin`), systemd-юнит с
жёсткими ограничениями, `install.sh`, `deploy.sh` (бэкап → pull → зависимости →
рестарт → health-check → автооткат), `rollback.sh`, таймер бэкапа, logrotate.

## Тесты

- `tests/api.test.js` — 23 сценария на временной БД (реклама, гонка за слот,
  суперлайки, 2FA, блокировка владельца, CSRF, rate limit, Secure-куки за прокси).
- `tests/e2e.test.js` — Playwright: регистрация, свайпы, матч, чат, посты,
  админка, разные ширины и темы. Требует установленного Chromium.
