# Wiutgram

[![CI](https://github.com/loshadtimur-dot/WiutGram/actions/workflows/ci.yml/badge.svg)](https://github.com/loshadtimur-dot/WiutGram/actions/workflows/ci.yml)

Сайт знакомств **только для студентов Westminster International University in Tashkent (WIUT)**: свайпы, матчи, realtime-чаты, посты, истории, статистика, уведомления, Aura Table, косметика профиля (баннеры, значки, подарки), реклама по часам и Центр управления для владельца. При регистрации доступен только WIUT — другие университеты отключены. Интерфейс на русском, код и комментарии на английском.

## Косметика, подарки и Aura Table

- **Aura Table** (`/aura`) — таблица популярности по подписчикам: чем больше подписчиков, тем выше место. Есть подиум топ-3 и общий список с кнопкой подписки.
- **Баннеры профиля** — 12 вариантов (градиенты, звёзды, сетки). Пользователь открывает «Косметика» в профиле и ставит доступный баннер или нажимает «Разблокировать». Доступ выдаёт владелец вручную после оплаты в Telegram: **20 000 сум за месяц**, можно выдать на месяц или год.
- **Значки** — 10 детализированных SVG-значков (дракон, чёрный паук, лиса, сова, феникс и другие). Видны всем в профиле, но поставить может только владелец через `/admin?section=cosmetics` по username — на месяц или год.
- **Подарки** — 25 видов: обычные, редкие, эпические, легендарные и админский (чёрная роза с анимированными звёздами). Покупаются только вручную через Telegram владельца, цены и редкость меняются в админке. Подарок можно отправить в чате, переподарить, скрыть из профиля или поставить фоном имени — фон профиля окрашивается по редкости.
- Владелец видит в админке инвентарь каждого пользователя, может выдавать и отзывать значки/баннеры/подарки, менять цены, редкость и Telegram для покупок.

Пароли пользователей хранятся только как bcrypt-хэш: посмотреть их нельзя никому, включая владельца. Вместо этого в карточке пользователя есть история входов, IP, активные сессии, генерация временного пароля с обязательной сменой и сброс сессий.

## Быстрый старт

```bash
npm install
npm start
```

Откройте <http://localhost:3000>. Для разработки с автоперезапуском: `npm run dev`.

Папки `data/` и `uploads/` создаются автоматически. База — `data/app.db` (SQLite, WAL). Если нативный `better-sqlite3` недоступен, сервер автоматически использует встроенный `node:sqlite`.

## Владелец сайта

**Владелец сайта это тот, кто зарегистрируется первым. Сделайте это сразу после запуска.**

- Первый реальный пользователь (не демо) становится `owner`; проверка выполняется в транзакции.
- `/admin` и все `/api/admin/*` доступны только владельцу. Остальным, включая гостей, сервер отвечает `404`.
- Пароль владельца — минимум 10 символов. Хранится только как bcrypt-хэш; посмотреть его нельзя никому.
- Владельца нельзя забанить, удалить или понизить. Передача владения: раздел «Данные» → «Передача владения» (пароль + слово `ПЕРЕДАТЬ`).
- Демо-профили не влияют на назначение владельца и не могут входить.

## Демо-данные

```bash
npm run seed
```

Создаёт 30 демо-профилей из Ташкента с университетами, курсами, районами, постами, историями и матчами в сторону первого реального пользователя. Пароль каждого демо-профиля генерируется случайно (`crypto.randomBytes`), нигде не сохраняется в открытом виде и не выводится; вход в демо-аккаунты запрещён сервером. Удалить демо можно в Центре управления → «Данные».

## Реклама по часам

Реклама — только изображение (JPG, PNG или WEBP) в пропорции **4:1**, рекомендуется **1600×400 px**. Один оплаченный час показывает один баннер одновременно на экране свайпов и в профилях (по умолчанию пакет; владелец может продать только одно место).

- Публичная страница **`/advertise`** работает без входа: сетка 24 часов по Ташкенту, вид «День» и «Неделя», быстрый выбор, сумма со скидками, заявка и окно «Напишите администратору в Telegram» с кодом вида `AD-7K3F`.
- Сайт **не принимает платежи**. Согласование и оплата — в Telegram владельца.
- Если час не продан, показывается свой блок «Здесь может быть ваша реклама» (режим `house`) или место скрывается (`hidden`) — настраивается.
- Все баннеры помечены «Реклама», клики идут через `/api/ads/click/...` с редиректом только на сохранённую ссылку.

### Как указать свой Telegram

1. Войдите как владелец → `/admin` → **Реклама** → **Настройки**.
2. В поле «Telegram для рекламы» введите username без `@` (5–32 символа, латиница, цифры, `_`).
3. Нажмите «Проверить ссылку» и сохраните. Username сразу появится на `/advertise` и в окне заявки.

Там же задаются цена за час (по умолчанию **15 000 сум**), горизонт бронирования, минимальное время до начала, максимум часов в заявке, скидки за объём, режим fallback, включение мест по отдельности, правила размещения и тексты своего блока.

### Раздел «Реклама» в панели владельца

- **Календарь** — сетка дней × 24 часа (неделя или 2 недели), протяжка мышью по свободным часам, красная точка у брони без баннера, режим «Список».
- **Создание/редактирование брони** — рекламодатель, Telegram, приватная заметка, места показа, часы (включая «каждый день с 20:00 до 22:00 на N дней»), цена, статус оплаты, баннеры, ссылка и alt-текст.
- **Баннеры** — загрузка с обрезкой 4:1 (перетаскивание, масштаб, колесо), предупреждение о низком качестве, экспорт в 1600×400 WEBP до ~400 КБ, библиотека и удаление (по паролю).
- **Заявки** — статусы, заметки, «Создать бронь по заявке», бейдж новых заявок в меню и уведомление в колокольчик.
- **Кампании** — поиск и фильтры, статистика (показы, уникальные, клики, CTR), публичная ссылка отчёта `/ad-report/<token>`, пересоздание токена, дублирование, отмена с причиной, экспорт CSV.
- **Доход** — оплачено за месяц и всего, ожидание оплаты, возвраты, загрузка слотов на 7 и 30 дней, топ рекламодателей, неоплаченные брони, экспорт CSV.

Защита: `UNIQUE(placement, hour_start)` плюс транзакционная проверка исключают двойную продажу; параллельные запросы проверяются тестом (20 запросов — ровно один успешный). Публичные ответы не раскрывают, кто купил час. Показы считаются один раз в час на посетителя, уникальность — по id или хэшу IP+UA с суточной солью.

## Суперлайки

Бесплатно начисляется 5 суперлайков в день. Купленный пакет не сгорает при ежедневном обновлении и расходуется только после бесплатных.

- В профиле есть карточка «Суперлайки» с балансом и кнопкой покупки; отдельная страница — **`/superlikes`**.
- Пакет по умолчанию: **100 суперлайков за 10 000 сум**. Количество, цена, Telegram и текст инструкции по оплате настраиваются в `/admin?section=superlikes`.
- Оплата — вручную, по той же схеме, что и реклама: пользователь отправляет заявку (код `SL-XXXXX`), переводит сумму и пишет владельцу в Telegram. Владелец в разделе «Суперлайки» нажимает «Начислить» — пакет сразу добавляется к балансу.
- Повторное подтверждение невозможно: статус проверяется в транзакции, поэтому пакет не начислится дважды. Заявки в ожидании показываются в бейдже меню и в уведомлениях владельца.

## Безопасность владельца

- **2FA (TOTP)** в `/admin?section=security`: QR-код и секрет, подтверждение кодом, 10 одноразовых резервных кодов (хранятся только хэшами), отключение по паролю и коду. Секрет TOTP хранится зашифрованным (AES-256-GCM) ключом, производным от `JWT_SECRET`.
- **Защита входа**: после 5 неудачных попыток аккаунт владельца временно блокируется на 15 минут, ответы замедляются прогрессивно, в панель приходит уведомление с IP и временем.
- **Сессии**: список активных устройств, завершение любой сессии, «выйти на всех других устройствах», история входов и неудачных попыток.
- **Смена пароля** (минимум 10 символов) прямо на странице безопасности.
- `X-Robots-Tag: noindex` для `/admin` и `/api`, `robots.txt` закрывает `/admin` и `/api`.

## Центр управления

- **Обзор** — пользователи, новые за 24 ч / 7 / 30 дней, онлайн, матчи, сообщения, посты, истории, лайки, жалобы, графики за 30 дней, распределение по университетам, курсам, полу и возрасту.
- **Реклама** — см. выше.
- **Суперлайки** — заявки на покупку пакета (начислить/отклонить с комментарием), настройки количества, цены, Telegram и инструкции по оплате, бейдж новых заявок.
- **Пользователи** — поиск и фильтры, массовые действия, экспорт CSV/JSON, карточка со всеми полями профиля, фото, контентом, активностью, переписками (по паролю и причине), сессиями и историей входов, сменой/генерацией пароля, баном по сроку, теневым баном, верификацией, заметками, удалением и входом как пользователь (только просмотр по умолчанию).
- **Университеты** — порядок, добавление, переименование, скрытие, удаление с переносом студентов, объединение, импорт/экспорт, заявки пользователей.
- **Контент и жалобы** — посты, истории, комментарии, очередь жалоб с решениями, объявления по всем или выбранному университету.
- **Настройки** — название, регистрация, режим обслуживания, лимиты, заявки на университеты. Регистрация с 16 лет.
- **Журнал** — только чтение: время, действие, цель, до/после, IP владельца.
- **Безопасность** — 2FA, сессии, входы, пароль.
- **Данные** — резервные копии (`VACUUM INTO`), размер базы и `uploads/`, демо-данные, передача владения.

Опасные действия требуют повторного пароля владельца (10 минут). Панель автоматически выходит после 30 минут бездействия. Ответы админ-API отдаются с `Cache-Control: no-store`.

## Город, университеты и приватность

- Город один — Ташкент (`CITY` в `config.js`). Выбора города, геолокации и расстояний нет.
- Вместо расстояния — необязательный район Ташкента; настройка «скрыть расстояние» заменена на «скрыть район».
- Список университетов хранится в БД и заполняется при первом запуске. Управляет им только владелец; изменения сразу видны в регистрации, фильтрах и профилях.
- Сейчас активен только **WIUT**: остальные университеты остаются в базе выключенными (`is_active = 0`), поэтому старые профили не ломаются, а регистрация и фильтры показывают только Westminster. Регистрация без `university_id` тоже получает WIUT.
- Фильтры колоды: возраст, университет, курс, приоритет «сначала мой университет». Теневой бан исключает пользователя из колод, поиска и Обзора.

## Безопасность

- Сессии в таблице `sessions`, JWT содержит `sid`; проверяются отзыв сессии и `token_version`.
- Пароли — только bcrypt. API не возвращает email, IP и хэши в публичных ответах.
- CSRF-проверка по `Origin`/`Referer` для небезопасных методов, `SameSite=Lax`, `X-Requested-With` на клиенте.
- Усиленный rate limit на `/api/admin/*`, лимит 5 заявок на рекламу в час с одного IP.
- Загружаемые баннеры проверяются по magic bytes и размерам; SVG, GIF и HTML отклоняются. Файлы отдаются с `X-Content-Type-Options: nosniff`.
- Все SQL-запросы — prepared statements; пользовательский HTML нигде не вставляется (текст выводится через `textContent`).

## Запуск на сервере

1. Установите Node.js 18+ и зависимости:

```bash
npm ci --omit=dev
cp .env.example .env
```

2. Заполните `.env`: `JWT_SECRET` (`openssl rand -hex 48`), `PORT`, `TRUST_PROXY=1` за nginx/Caddy, `NODE_ENV=production`.
3. Запустите через pm2 или systemd:

```bash
# pm2
npm i -g pm2
pm2 start deploy/ecosystem.config.js --env production
pm2 save && pm2 startup

# systemd
sudo cp deploy/uni-lovers.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now uni-lovers
```

4. Поставьте HTTPS-прокси: примеры в `deploy/Caddyfile` и `deploy/nginx.conf`. Caddy сам получает сертификат; для nginx используйте `certbot --nginx`.

`TRUST_PROXY` обязателен за прокси, иначе rate limit увидит IP прокси. В production cookie сессии передаётся только по HTTPS (`secure`). По `SIGTERM` сервер аккуратно закрывает соединения и сохраняет счётчики активности.

Проверка: `curl https://wiutgram.up.railway.app/api/health` → `{"ok":true,...}`.

### Резервное копирование

```bash
chmod +x deploy/backup.sh
# каждый день в 03:15
15 3 * * * /srv/uni-lovers/deploy/backup.sh >> /var/log/uni-lovers-backup.log 2>&1
```

Скрипт делает `sqlite3 .backup` базы и архив `uploads/` в `backups/`, хранит 14 дней. Копии можно также создавать в панели: **Данные → Создать резервную копию**.

### Обновление проекта

```bash
cd /srv/uni-lovers
./deploy/backup.sh
git pull
npm ci --omit=dev
sudo systemctl restart uni-lovers   # или: pm2 restart uni-lovers
```

Миграции базы выполняются при старте и только добавляют таблицы и колонки — существующие данные не удаляются. Перед обновлением всё равно сделайте копию базы. Статика отдаётся с `Cache-Control: no-cache` для HTML/JS/CSS, поэтому после деплоя браузеры получают свежие файлы.

## Тесты

```bash
npm run test:api   # node:test + fetch на временной БД и папке загрузок
npm run test:e2e   # Playwright/Chromium, 375 / 768 / 1440, светлая и тёмная темы
```

Тесты поднимают собственный сервер на портах 3199 (API) и 3198 (E2E) с `UNI_DB_FILE` и `UPLOADS_DIR` во временной папке и удаляют её после прогона. Реальная `data/app.db` и `uploads/` не затрагиваются.

Для E2E нужен Chromium: `npx playwright install --with-deps chromium` (на минимальном Linux дополнительно нужны системные библиотеки NSS/GTK и шрифты с кириллицей, например `fonts-dejavu-core`).

API-тесты покрывают: первый пользователь = владелец, второй = пользователь, 18−, несуществующий университет, 404 на админку для гостя и пользователя, отсутствие хэшей паролей в ответах, SQL-инъекции, CSRF по Origin, 2FA (вход, резервные коды, отключение), блокировку после неудачных попыток, загрузку баннеров (валидный PNG, SVG, GIF, неверная пропорция), показ баннера в обоих местах, fallback, уникальные показы, редирект только на сохранённый URL, скидки, заявки, конвертацию заявки, 20 параллельных броней на один час (ровно одна успешна), отмену с освобождением часов, публичный отчёт по токену и rate limit заявок.

E2E проверяет: лендинг и `/advertise` на трёх ширинах без горизонтальной прокрутки и ошибок консоли, выбор часов и окно Telegram, мобильную сетку 4 колонки в тёмной теме, показ оплаченного баннера на свайпах и в профиле, календарь и бронирование в панели, настройки рекламы, страницу безопасности владельца, отсутствие горизонтальной прокрутки админки на 375 px и запрет админки обычному пользователю.

Скриншоты сохраняются в `screenshots/` (папка в `.gitignore`).

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `PORT` | порт HTTP-сервера (по умолчанию 3000) |
| `JWT_SECRET` | секрет подписи сессий и шифрования 2FA; если не задан — `data/secret.txt` |
| `UNI_DB_FILE` | путь к базе SQLite (по умолчанию `data/app.db`) |
| `UPLOADS_DIR` | папка загрузок (по умолчанию `uploads/`) |
| `TRUST_PROXY` | `1` за nginx/Caddy, `false` — не доверять прокси |
| `NODE_ENV` | `production` включает secure-cookie |
| `APP_URL` | публичный адрес сайта для абсолютных ссылок в `sitemap.xml` и письмах |
| `RESEND_API_KEY` / `BREVO_API_KEY` | ключ почтового провайдера; без него подтверждение почты отключено |
| `MAIL_FROM` | адрес отправителя писем, например `Wiutgram <noreply@wiutgram.app>` |
| `MAIL_DEBUG` | `1` — писать письма в лог вместо отправки (для локальной проверки) |
