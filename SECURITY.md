# Security policy / Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Напишите владельцу проекта в Telegram или на
контактный адрес, указанный в Правилах на сайте. Укажите шаги воспроизведения,
затронутые эндпоинты и версию (тег вида `v1.0.0`).

Мы подтверждаем получение в течение 72 часов и сообщаем решение после проверки.
Пожалуйста, не публикуйте детали до исправления.

## Что защищать в первую очередь

- Персональные данные и фотографии пользователей (`/media/*`, приватное хранилище).
- Аккаунт владельца: пароль, 2FA, sudo-подтверждение опасных действий.
- Секреты: `JWT_SECRET`, ключи VAPID, SMTP, Telegram-бот, токены GitHub.

## Правила для разработки

- Секреты только в переменных окружения или файлах вне репозитория
  (`.env`, `/etc/uni-lovers/uni-lovers.env`). В коде и документации их нет.
- Любая запись данных требует проверки прав на сервере; клиентским идентификаторам
  пользователя не доверяем.
- Все мутации проходят проверку Origin (CSRF) и лимиты запросов.
- Загруженные изображения перекодируются, метаданные удаляются.
- Перед публикацией изменений: `npm run lint`, `npm run test:api`, `npm run test:e2e`.

## Поддерживаемые версии

Актуальная ветка `main`. Старые теги не получают патчей безопасности.
